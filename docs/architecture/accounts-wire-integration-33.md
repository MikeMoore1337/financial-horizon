## Real executable acceptance

The synthetic CI sequence:

1. Start disposable PostgreSQL 17 with reviewed Alembic migrations and FORCE
   RLS; create an independent real SQLite AuthStore session with FH cookie
   bridge. No personal or production data are involved.
2. Create two synthetic accounts with explicit starting balances, then
   obtain a true server snapshot, entity revisions and strong ETag.
3. Run the actual TypeScript encodeTransfer source using Node 24, and send
   its exact JSON body, If-Match and Idempotency-Key to the real FastAPI
   endpoint. Transfer **1000 RUB** (100000 kopecks), including an account
   with a negative balance. The two signed postings cancel exactly,
   preserving overall account assets.
4. Re-submit the same envelope: return the same receipt as a replay without
   creating a second transfer or applying another debit.
5. Invoke TypeScript encodeReversal with the original transaction UUID and
   exact account revisions. The HTTP server posts compensating entries.
   After cancellation all account balances equal the initial amounts.
   Duplicate cancellation replay does not change money.
6. Use a second AuthStore login and PostgreSQL profile: an attempted foreign
   account transfer is denied despite supplying an apparently valid UUID.
   A stale If-Match causes HTTP 412 and leaves balances untouched.
7. Verify that the full revision-ordered change feed contains the exact
   same immutable transaction images as the current authoritative snapshot.

There is no handwritten Python imitation of the TypeScript command: the
JSON is generated by importing the production source .ts encoder in Node.
