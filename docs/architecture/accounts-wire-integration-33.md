## Real executable acceptance

The synthetic CI sequence:

1. Start disposable PostgreSQL 17 with reviewed Alembic migrations and FORCE
   RLS; create an independent real SQLite AuthStore session with FH cookie
   bridge. No personal or production data are involved.
2. Create two synthetic accounts with explicit starting balances, then
   obtain a true server snapshot, entity revisions and strong ETag.
3. Run the actual TypeScript encodeTransfer source using Node 24, and send
   its exact JSON body, If-Match and Idempotency-Key to the real FastAPI
   endpoint. Transfer **1000 RUB** (100000 kopecks), including an account
   with a negative balance. The two signed postings cancel exactly,
   preserving overall account assets.
4. Re-submit the same envelope: return the same receipt as a replay without
   creating a second transfer or applying another debit.
5. Invoke TypeScript encodeReversal with the original transaction UUID and
   exact account revisions. The HTTP server posts compensating entries.
   After cancellation all account balances equal the initial amounts.
   Duplicate cancellation replay does not change money.
6. Use a second AuthStore login and PostgreSQL profile: an attempted foreign
   account transfer is denied despite supplying an apparently valid UUID.
   A stale If-Match causes HTTP 412 and leaves balances untouched.
7. Verify that the full revision-ordered change feed contains the exact
   same immutable transaction images as the current authoritative snapshot.

There is no handwritten Python imitation of the TypeScript command: the
JSON is generated by importing the production source .ts encoder in Node.

## Server-authoritative read model

`src/domain/accounts/server-snapshot.ts` adapts a COMPLETE (HTTP 200)
server-owned `/api/finance/v1/state` snapshot into the account/ledger model
already consumed by the owner-approved React Accounts component. It accepts
the profile UUID and verified actor ID from the authenticated FH host, never
from a client HTTP command. The v1 read deliberately does not expose the
actor field; this project is currently owner-only.

The adapter rejects a truncated/206 page, foreign profile, missing actor
verification, duplicate ID within a table, unsupported money/currency,
inconsistent reserved/available balance, missing immutable transaction,
missing linked loan/settlement void fact and unbalanced reversal. PostgreSQL
has independent UUID keys **per entity table**, so the adapter does not
incorrectly require globally distinct IDs across unrelated tables. A legacy
positive/negative posted balance is reconstructed exactly in integer kopecks;
it never infers missing opening balances or treats planned obligations as
paid.

The real `backend/finance_api/tests/test_ts_wire_roundtrip.py` now also
executes the ACTUAL TypeScript snapshot adapter against an authenticated
FastAPI/PostgreSQL `/state` response, then performs a transfer and verifies
exact assets, signed postings and cross-user rejection. The
`tests/accounts-server-snapshot.test.mjs` cases validate failed linked
reversals, amount mismatches, valid archived UTC timestamps, full-page
requirements and original owner-only actor binding.

The domain's `monthlyCashFlowMinor` categorizes the **compensating reversal
in the original payment's direction**; an annulled expense is no longer
reclassified into artificial income and a settlement refund likewise does
not invent another expense. This is already synchronized into #84, #111 and
the approved UI PR #120.
