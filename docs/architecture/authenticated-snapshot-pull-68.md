# #68 - явная проверка серверного снимка FH (кандидат, OFF)

**Режим: source-only, без активации.** Модуль `src/cloud/authenticated-snapshot-pull-candidate.mjs` не подключён к `app.js` или установленной PWA. Не запрашивает деньги в фоне, не пишет в IndexedDB и не запускает синхронизацию.

## Контракт

- Вызывается только после проверки FH-сессии и отдельного разблокирования AES-GCM хранилища #34, с явным `explicitReadConsent=true`.
- Принимает только HTTPS того же origin (или `http://127.0.0.1` для изолированных тестов). GET использует `credentials=same-origin`, `no-store`, `redirect=error`; отменяется вместе с текущей разблокированной сессией.
- Скачивает максимум 25 страниц, каждая максимум 2 МБ, требует сильный одинаковый ETag, связанный курсор, 206 для неполной и 200 для конечной страницы. `verifyFinanceSnapshotPagesCandidate` проверяет UUID, профиль, ревизии, порядок, суммы и целостность сущностей перед возвратом результата.
- Возвращает только проверенный `pages` для отдельной `initializeEncryptedCloudCacheCandidate`; не изменяет старую бухгалтерию, текущий зашифрованный snapshot, неподтверждённый outbox и конфликты.

## Требуется до production

Подключить защищённую разблокировку и жизненный цикл FH-сессии к PWA, атомарную зашифрованную запись подтверждённого серверного снимка, восстановление/повтор команд и явное пользовательское разрешение конфликтов. Реальные два устройства, две вкладки, offline/restart/logout и независимые проверки #70 остаются обязательными. Выключенный модуль и его синтетические тесты не удовлетворяют приёмке #68.
