**Дата:** 2026-11-06  
**Статус:** AUDITED_WITH_OPEN_FINDINGS; Issue #44 сохраняется OPEN. Повторная проверка после PR #52 - 2026-11-06, **4 P1 остаются открытыми**, UX44-01 закрыт по результатам повторного аудита.  
**Объект:** точный снимок main: [03e719a34b72f8354d1d3e730a4f8d4c4f254211](https://github.com/MikeMoore1337/financial-horizon/commit/03e719a34b72f8354d1d3e730a4f8d4c4f254211).  
**Область:** обзор, календарь, обязательства, кредиты, настройки, страница аккаунта, диалоги, обе темы и гостевая PWA.

## 1. Проверенная методика и ограничения

- Репозиторий прочитан и клонирован в отдельный временный каталог по указанному SHA. Исходный main, продакшен, действующие ветки и код приложения не изменялись.
- Запущен локальный HTTP origin (127.0.0.1:18744), Microsoft Edge Chromium 156.0.4314.58 в режиме headless, Playwright 1.65.0, @axe-core/playwright 4.14.0. Записи хранились в **настоящей IndexedDB** и использовался настоящий Service Worker, а не подменённые модули.
- Запуск существующих тестов: **83 PASS / 0 FAIL**. Исходный набор покрывает логику, но не является доказательством соответствия WCAG или реального Safari.
- Матрица фактических браузерных измерений: **56 из 60** комбинаций (320, 360, 393, 768, 1440, 2560 CSS px × 2 темы × 5 разделов). Четыре перехода в первоначальном прогоне 320 px завершились тайм-аутом автоматизации. Дополнительный изолированный прогон на 320 px подтвердил работу нажатия на «Кредиты» и активации Enter; эти тайм-ауты **не квалифицированы как подтверждённый дефект навигации**.
- **23 запуска axe:** 20 состояний (393 и 1440 px × пять разделов × обе темы), страница аккаунта на 393 px и два открытых диалога (импорт XLSX, создание записи). Проверялись правила WCAG 2 A/AA, 2.1 A/AA, 2.2 AA, доступные axe.
- Скриншоты и журнал метрик: [машинные результаты](./evidence-44/results.json). Финансовые записи и XLSX-файл **полностью синтетические**; персональные данные, токены, адреса локальной системы, дампы настоящих баз не публиковались.
- Проверки настоящего iPhone, установленного Safari PWA, macOS Safari, VoiceOver, системной строки iOS и физической клавиатуры на Mac: **NOT_RUN - устройства недоступны через этот исполнитель**. Chromium/Edge не объявляется Safari.
- Регистрация, реальный email-вход, серверный выход, восстановление пароля и смена email на действующем canary backend: **NOT_RUN**. В локальном сервере нет backend; подтверждена только клиентская навигация режимов и соответствующие существующие модульные тесты. Проверять реальные учетные записи на production без тестового окружения и разрешенного сценария не проводилось.
- Ничего не внедрялось и не развёртывалось. Потоки #8, #31, #32 не затронуты.

### Принципы классификации

**P0** - невозможность безопасно использовать приложение, потеря данных или критический доступ к чужим данным; **P1** - критичный сценарий/доступность или подтвержденное нарушение обязательной адаптивности; **P2** - локальная проблема семантики, доступности или удобства без доказанной потери данных.  
**BROWSER** - воспроизведено в настоящем движке Edge; **AXE** - объективное срабатывание правила на реальном DOM; **CODE** - подтверждённая характеристика текущего исходного кода, требующая дополнительной пользовательской проверки.

## 3. Отдельно: нестабильный результат автоматизации, не подтверждённый дефект

Первоначальный проход матрицы на 320 px вызвал четыре тайм-аута при переходе из «Платежи» в «Кредиты» и «Ещё» (обе темы): Playwright сообщает о перехвате точки клика элементами страницы. **Однако повторная изолированная проверка с закрытым диалогом подтверждения прошла: обычный клик на «Кредиты» PASS, активация Enter PASS.** В одном диагностическом проходе незакрытый диалог также перехватывал события - это корректное модальное поведение и ошибка тестового сценария.

Поэтому статус этого наблюдения: **UNSTABLE / NEEDS_REPRO**. Не создавать по нему отдельную Issue и не утверждать, что нижняя навигация всегда не работает. В #31 стоит добавить надёжный тест последовательности «Обзор → Календарь → Платежи → Кредиты → Ещё» с заранее закрытыми модалками и проверкой document.elementFromPoint, scrollX/scrollY, скролла и реального нажатия.

## 12. Linux CI - причина переполнения на 2 px

В GitHub Actions Linux/Chromium проверка кредита с длинным синтетическим названием нашла второе переполнение: при viewport 320 CSS px корневой scrollWidth=322 (повторно в retry), хотя на Windows тест проходил. Диагностика выявила правый край элементов .loan-stats > div с подписями «Осталось ориентировочно» и «День платежа» на координате 321.63 px.

Причина: grid-template-columns:repeat(2,1fr) сохранял минимальную внутреннюю ширину ячеек. Исправлено точечно: repeat(2,minmax(0,1fr)) и min-width:0;overflow-wrap:anywhere у .loan-stats > div. В E2E сохранена строгая проверка горизонтального скролла и добавлена проверка правых краёв всех ячеек статистики.

Следующий гейт: все обязательные проверки Linux CI на точном PR SHA. Реальный Safari iOS/macOS и VoiceOver по-прежнему NOT_RUN.
