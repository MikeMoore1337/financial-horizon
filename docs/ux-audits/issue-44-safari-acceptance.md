# Financial Horizon #44 - физическая приёмка iOS/macOS Safari и VoiceOver

**Статус: NOT_RUN.** На момент подготовки аудита к авторизованному исполнителю были подключены Windows и Linux-устройства, но отсутствовали доступные iPhone, iPad или Mac с Safari/VoiceOver. Этот документ - протокол будущей ручной проверки, не свидетельство выполнения.

**Применять к установленной production-версии приложения только после внедрения согласованных UX-исправлений и проверки точного развёрнутого SHA.** Проверять на отдельном тестовом профиле с исключительно синтетическими данными; не включать в скриншоты личный бюджет, email, токены, названия устройств и сведения об инфраструктуре.

## iPhone: Safari + установленная PWA

**Подготовка:** открыть приложение через защищённый HTTPS, выбрать «Продолжить без регистрации», добавить только тестовые доход/расход или включить встроенный пример. Не использовать реальный бюджет. Сохранить шифрованную копию синтетического набора и отдельно проверить возможность отменить восстановление. При использовании установленной PWA учитывать, что её данные и данные Safari могут быть изолированы.

1. **Системная строка и верхняя панель.** В Safari и установленной PWA переключить светлую → тёмную → светлую тему без перезагрузки. Проверить физический цвет фона за часами/индикаторами и отсутствие перекрытия заголовка, белой/тёмной полосы неправильной темы, скачка высоты. Затем свернуть и открыть PWA, повернуть экран. **PASS:** цветовая схема согласована, контент не перекрыт.
2. **Нижняя панель и безопасные отступы.** На узком iPhone прокрутить каждый из пяти экранов к началу/концу, проверить попадание пальцем в пять пунктов, видимость последней кнопки/карточки над dock и визуальную симметрию, в том числе при появлении/скрытии Safari toolbar. **PASS:** нет скрытого содержимого или ложных срабатываний.
3. **Адаптивность/динамический текст.** Проверить увеличенный текст в настройках iOS, масштаб страницы 200%, вертикальную и горизонтальную ориентацию, длинное название операции. **PASS:** не требуется горизонтальная прокрутка всей страницы для обычного текста; редактирование и подтверждение доступны.
4. **Экранная клавиатура.** Открыть создание записи, установить фокус в нижнее поле (сумма/дата/категория), проверить перемещение модального диалога, доступ к «Сохранить» и «Отмена», возврат фокуса после закрытия. Повторить с экраном импорта/пароля резервной копии. **PASS:** клавиатура ничего не перекрывает, активное поле видно и доступно.
5. **VoiceOver.** Настройки iOS → Универсальный доступ → VoiceOver. Свайпами пройти заголовок, пять пунктов дока, плюс, карточки и ссылки, открыть создание операции, переключить поля/форму, закрыть через «Отмена» и проверить возврат фокуса. **PASS:** каждое действие имеет русское понятное доступное имя, состояние выбранного элемента озвучивается, нет «Кнопка» без названия, можно выполнить действие двойным касанием.
6. **Модальные окна.** Проверить сценарий импорта синтетического XLSX: список подготовленных строк прокручивается с VoiceOver/клавиатуры, «Отмена» ничего не сохраняет; подтверждение добавляет только ожидаемые данные. Проверить шифрованный экспорт, затем восстановление с подтверждением замены. **PASS:** диалог сообщает заголовок и фокус ограничен модальностью, ошибки озвучиваются.
7. **Офлайн/повторный запуск.** После установки запустить PWA, отключить сеть, открыть сохранённые данные, повторно запустить PWA, вернуть сеть и проверить отсутствие произвольного сброса темы/потери записей. **PASS:** локальные данные сохранены, offline shell не выдаёт устаревшие части UI за новые.
8. **Аккаунт.** При разрешённой тестовой среде и синтетическом email выполнить вход → подтверждение сессии → выход → возврат на форму → повторный вход, отдельно восстановление пароля и отрицательный сценарий. **PASS:** маршрут и VoiceOver доступны; отсутствие реального backend нельзя засчитать как PASS.

## macOS Safari

1. Открыть Safari и (при поддержке ОС) веб-приложение, изменить светлую/тёмную тему, перезапустить окно, проверить контраст, фокус, верхнюю панель и системное поведение.
2. Пройти все разделы только клавиатурой (Tab/Shift+Tab, Space/Enter, Escape), включая кнопки удаления с подтверждением, ввод с ошибками, импорт XLSX, экспорт/восстановление.
3. Включить VoiceOver (Command+F5, если настроено), пройти landmarks, заголовки, названия кнопок, статусные сообщения, все диалоги. Зафиксировать фактически озвученные подписи и элементы без имён.
4. Открыть приложение на узком окне (~320/393/768 CSS px) и на широком (1440/2560 px), проверить перетекание, масштаб 200%, горизонтальную прокрутку.
5. Проверить реальный сценарий logout/login только с разрешённым синтетическим аккаунтом и без публикации токенов/почты.

## Формат результата

Для каждого сценария в отдельной квитанции фиксировать:
- test_id, device, os_version, safari_version, mode, ui_theme, viewport_css_px, zoom_or_text_size;
- steps, expected, actual, PASS/FAIL/BLOCKED, evidence_path, commit_sha, notes;
- видео/снимки с синтетическими данными без учётных данных;
- дефектное поведение, шаги воспроизведения, уровень P0/P1/P2, связь с уже открытой UX44-матрицей.

**Запрещено:** маркировать эту матрицу PASS до исполнения на физических устройствах, выдавать Playwright WebKit на Windows/Linux за Safari iOS, копировать настоящие банковские/финансовые данные в тесты или закрывать #44 при незавершённых обязательных физических проверках.
